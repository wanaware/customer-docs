# Create and manage Structures

**Outcome:** Add a named Structure that reflects a real organizational or logical grouping.

**For:** Customer administrators and engineers
**Permission:** Structures; create or update permission for changes
**Time:** 5–10 minutes
**Changes made:** Creates or changes shared organizational data

## Before you start

- Decide what the Structure represents and who owns its naming.
- Search for an existing Structure before creating another one.
- Start with a small hierarchy. Add detail only when it supports a real workflow.
- In a shared demo, obtain approval before adding, moving, or deleting Structures.

## Add a Structure

1. Open **Functions → Structures**.
2. Select **Add Structure**.
3. Choose the required **Structure Type**.
4. Enter a clear **Structure Name**.
5. Save the Structure.

**Expected result:** The new Structure appears in the hierarchy and can be found with **Search**.

## Edit a Structure

1. Find the Structure by name.
2. Open its action menu and choose the edit action.
3. Update **Structure Type** or **Structure Name** only after checking where the Structure is used.
4. Save the change.

**Expected result:** The hierarchy reloads with the new value, and attached records remain associated.

## Attach operational context

Use the supported attach actions to associate Elements or other available records with the appropriate Structure. Confirm the target Structure before saving; similarly named branches can represent different areas of the business.

## Check your result

Search for the Structure, expand its branch, and confirm that its parent, children, and attached records match the intended model.

## Delete a Structure

Deletion can affect attached records and child branches.

1. Open **Delete structure…** only after reviewing the branch.
2. Read the confirmation and dependency information.
3. Use **Delete & continue** only when the remaining records have an approved destination or no longer apply.

Do not delete a Structure to correct its name; edit it instead.
