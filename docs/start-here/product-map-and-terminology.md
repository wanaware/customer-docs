# Product map and terminology

The left navigation shows only the areas available to your company and role.

## Main product areas

| Area | What you use it for |
| --- | --- |
| **Launchpad** | Review workspace summaries and move into a detailed workflow. |
| **Functions → Structures** | Model organizational or logical hierarchy. |
| **Functions → Assets** | Review Discovery and Inventory, edit asset details, and explore relationships. |
| **Functions → Elements** | Manage Applications, Services, Sites, and their Collections. |
| **Administration → General** | Manage permitted company settings. |
| **Administration → Integrations** | Connect supported data sources and run available collection jobs. |
| **Administration → IAM** | Invite members and assign roles. |
| **Administration → Asset Types** | Define custom asset schemas and their lifecycle. |
| **Administration → Service Catalog** | Manage approved catalog data for custom Asset Types. |
| **Administration → Billing** | Review plans, usage, payment settings, and billing history. |
| **Theme Settings** | Choose your personal Light or Dark appearance and an available preset. |

## Core terms

**Integration**
A managed connection between WanAware and a supported data source. Each provider can have its own adapter instructions.

**Asset**
A resource tracked by WanAware. An asset has an Asset Type, status, details, tags, and relationships.

**Discovery**
The workspace for assets that have been found or are still being reviewed.

**Inventory**
The maintained set of assets used throughout WanAware.

**Asset Type**
The schema that defines an asset's sections, fields, dependencies, and catalog support.

**Service Catalog**
Managed information used by an Asset Type, including manufacturers, models, modules, software, specifications, attributes, and compatibility where supported.

**Relationship**
A connection derived from supported data or created by a specific product flow. WanAware does not provide a general-purpose action for drawing arbitrary relationships.

**Structure**
A hierarchy made from supported Structure types such as Company, Organization, Group, and Vendor.

**Structure Tag**
An attachment to a Structure node. Structure Tags connect supported records, including Elements and Collections, to the hierarchy.

**Element**
An Application, Service, or Site used to represent an operational unit.

**Collection**
A named group of assets inside an Element.

**Role**
A named set of permissions. Roles control which pages and actions a member can use.
